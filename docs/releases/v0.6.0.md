# issuectl 0.6.0 — release notes (draft, 2026-05-31)

A v0.5.2 → v0.6.0 jump landed via two `/orchestrate` campaigns (14 + 9
worker nodes, all merged into main). Theme: **CLI-mode improvements** —
no kanban / web-board work in this release. 23 issues closed, 72 commits
since v0.5.2, 71 commits ahead of `origin/main`.

> This file is the human-oriented digest. `CHANGELOG.md` is the
> canonical record but its `[Unreleased]` section only captures
> batch 2 explicitly — batch 1 features arrived as `feat(*)`
> commits without per-feature CHANGELOG entries. **Treat this
> file as the comprehensive view** of what landed; before cutting
> the release tag, the `[Unreleased]` block should be backfilled
> from the "Batch 1 — landed without CHANGELOG entries" section
> below.

---

## Highlights

- **Dependency tracking**, **cycles**, **estimates**, **reviewer field**,
  and **recurring issues** — issuectl now covers most of the
  Linear-style "lightweight planning" surface, all in
  frontmatter, all offline.
- **Schema gets teeth**: declarative `required_when` rules (e.g.
  closing statuses imply `closed:` is set), `status_aliases` /
  `type_aliases` for migration, and schema-driven agent
  instructions in `issuectl context`.
- **Git becomes the event log**: `issuectl activity` / `timeline` /
  `changelog` / `metrics` — no event database.
- **CLI ergonomics**: `bulk`, `rename`, `open`, `pick`, `triage`,
  slug-prefix matching, shell completions, `scan-todos`, inbox
  drafts, `note --stdin/--from-file`, `attach`, descriptive
  title-derived slugs.
- **Content / interop**: first-class attachments + fixtures dirs,
  import/export for JSON / CSV / markdown / GitHub, heuristic
  duplicate detection.
- **Lifecycle**: stale detector + archive of old closed issues
  under `issues/archive/YYYY/MM/`.
- **Markdown DoD validation**: warn (or block, opt-in) on `→ done`
  with unchecked Acceptance Criteria.

## Behaviour changes worth knowing

- **Slug collision error** on `issuectl new --slug <existing>` is now
  actionable (names the colliding slug + path, suggests retry or
  omit `--slug`). Old terse error gone.
- **`/issue` skill** prefers descriptive 2-3 word `--slug` from the
  title; falls back to random when no obvious slug exists. CLI's
  own default (random when `--slug` is omitted) is unchanged.
- **`--json` envelope** unified across commands — clap usage
  errors now also flow through the JSON envelope, with a
  documented partial-success contract.
- **Slug prefix matching** is now central: every per-slug command
  benefits. Ambiguous prefixes print candidates and exit
  non-zero; no-match errors as before.
- **Archive read-through**: `ls`, `show`, `search`, etc. read the
  active + archive roots. Renamed issues are followed across
  archive moves.
- **DoD warning** on closing-status transitions when Acceptance
  Criteria is unchecked (per-rule strict mode still available
  via `dod.strict: true`).
- **`blocked_by` is reserved**: writing it via `--field` or PATCH
  custom-field is rejected with a hint pointing at
  `issuectl depend`.
- **Recurrences are UTC**: a per-definition `timezone:` field is a
  future enhancement.
- **`recurrence_of` / `occurrence` keys** are custom frontmatter — a
  repo schema that forbids extra keys must declare them
  explicitly.
